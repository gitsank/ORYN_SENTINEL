# ORYN_SENTINEL — AI Prompt-Injection Defense System v2.0

ORYN_SENTINEL is an adaptive AI firewall designed to identify and mitigate prompt-injection, jailbreak, obfuscation, and context-manipulation attacks in LLM-powered applications. Built around a layered detection pipeline, it combines deterministic input checks with a DeBERTa-based AI auditor and a Phi-2 response model.

> Hackathon project for Cosmic Fest 2026 — PS:1

## Key Capabilities

- **Layered threat detection:** Applies blacklist checks, regex-based pattern matching, and DeBERTa classification.
- **Dual-model architecture:** Uses DeBERTa as an auditor and Phi-2 as the response LLM.
- **Input normalization:** Handles encoded or obfuscated input patterns, including Base64, Unicode, and leetspeak transformations.
- **Context-aware analysis:** Considers conversation history to help identify multi-step prompt-injection attempts.
- **Intent extraction:** Flags covert, proxy, or hypothetical framing associated with suspicious requests.
- **Explainable decisions:** Provides a decision category and supporting reason, score, and intent information.
- **Output egress filtering:** Checks generated responses for sensitive information such as credentials, API keys, and personally identifiable information.
- **Adaptive pattern storage:** Stores blocked patterns to support future detection improvements.
- **Evaluation dashboard:** Presents detection metrics such as accuracy, false-positive rate, latency, and threat coverage.
- **Forensic logs:** Displays session-level telemetry for reviewing security decisions.
- **Red Team mode:** Includes 100+ test vectors for exercising detection behavior.

## Detection Pipeline

1. **Normalize input** — identify and decode supported obfuscation patterns.
2. **Tier 0: Blacklist filtering** — immediately screen known prohibited patterns.
3. **Tier 1: Regex matching** — check for recognizable jailbreak and injection patterns.
4. **Context risk assessment** — consider relevant conversation history.
5. **Tier 2: DeBERTa auditing** — classify input for additional threat signals.
6. **Intent analysis** — extract suspicious framing and intent indicators.
7. **Apply decision** — block, sanitize, or allow the request.
8. **Generate response** — invoke Phi-2 only when the request is allowed.
9. **Filter output** — inspect the response for sensitive data before returning it.
10. **Record evidence** — retain forensic information for review.

The README reports approximately **150 ms** for the AI threat-detection stage; response generation by Phi-2 may take longer.

## Technology Stack

- **AI / NLP:** DeBERTa, Phi-2, Hugging Face Transformers

- **Security techniques:** Blacklist filtering, regular expressions, input normalization, context-aware risk assessment, output filtering

## Run the Demo

### Google Colab (recommended for the demo)

1. Set the runtime to **GPU (T4)**.
2. Install dependencies:

   ```bash
   pip install -q accelerate pandas transformers gradio
   ```

3. Paste and run `oryn_sentinel_colab.py` in a notebook cell.
4. Open the Gradio link generated by the notebook.

### Local Setup

```bash
pip install -r requirements.txt
python oryn_sentinel_local.py
```

Open `http://127.0.0.1:7860` in your browser.

For low-memory or CPU-only environments, set `USE_CPU_ONLY_MODE = True`. To disable Phi-2 while retaining threat detection, set `LIGHTWEIGHT_MODE = True`.

## Demo Scenarios

- **Benign request:** Submit a general question and verify that it is allowed.
- **Jailbreak attempt:** Use a Red Team test case and inspect the block decision and explanation.
- **Multi-step attack:** Submit a sequence of messages to examine context-based risk scoring.
- **Encoded input:** Test a supported Base64-obfuscated payload.
- **Evaluation:** Review the metrics dashboard and forensic session logs.

## Project Focus

ORYN_SENTINEL explores practical LLM application security: layered defense design, prompt-injection detection, explainable decisions, adversarial testing, performance measurement, and auditability.

*Security note: this project is a defense prototype. Detection performance depends on the model, configuration, and test data; it should not be treated as a guarantee that every attack will be detected.*
